Azure charges for rg-insureassist
=================================

Deployment completed 2026-10-19 ~12:21 UTC (France Central).

Reading 1 - baseline, taken minutes after deployment
---------------------------------------------------
Query: Cost Management ActualCost, MonthToDate, grouped by Meter
  az rest --method post --url ".../Microsoft.CostManagement/query?api-version=2024-08-01"

Result: NO CHARGES RECORDED (no cost rows returned)

This is expected and is NOT evidence that the deployment is free. Azure cost
data lags usage by several hours, so a reading taken immediately after
deployment cannot show anything yet. The reading that matters is the later one
below.

The specific question being checked is whether the "Environment Management
Hour" meter ($0.125/hour in France Central) is billed for a Consumption-only
environment. The environment reports:

  workloadProfiles: [ { name: Consumption, workloadProfileType: Consumption } ]

and that meter is documented against Dedicated workload profiles, so the
expectation is that it is not charged. Expectation is not evidence, hence this
file.

Known fixed cost regardless: ACR Basic at $0.1666/day, for the registry that
holds the pushed image. ACR Tasks is not permitted on this subscription, so the
registry cannot be avoided by building server-side.

Reading 2 - about two hours after deployment
--------------------------------------------
Taken 2026-10-19 ~14:20 UTC, roughly two hours after the app went live.

  Cost Management ActualCost, MonthToDate, grouped by Meter : NO ROWS
  az consumption usage list --top 50                        : EMPTY

Still nothing. Azure's billing pipeline lags usage, commonly 8 to 24 hours on a
pay-as-you-go or Student subscription, so this reading does not answer the
question either.

Stated explicitly because it would be easy to misread: **an empty cost query is
not evidence that the deployment is free.** It is evidence that Azure has not
published the data yet. The two are different and only one of them is a reason
to relax.

What the exposure actually is, while this is unresolved:

  ACR Basic registry unit            0.1666 USD/day   certain
  Environment Management Hour        0.125  USD/hour  unknown whether it applies
  Container Apps vCPU + memory       negligible       min-replicas 0, no traffic

So the daily cost is either about **0.17 USD/day** (the meter does not apply to
a Consumption-only environment, which is the expectation) or about **3.17
USD/day** (it does). Over seven days that is either 1.19 USD or 22.19 USD, and
the subscription's remaining credit is around 88 USD.

Reading 3 - about thirty hours after deployment. THE QUESTION IS ANSWERED
-------------------------------------------------------------------------
Taken 2026-10-20 18:57 UTC, roughly 30 hours after the app went live. The data
exists this time.

  az rest --method post --url ".../resourceGroups/rg-insureassist/providers\
      /Microsoft.CostManagement/query?api-version=2024-08-01"
  body: ActualCost, MonthToDate, granularity None, grouped by Meter

  Meter                          Cost (EUR)
  -----------------------------  ----------
  Basic Registry Unit              0.150788
  Standard vCPU Active Usage       0.014903
  Standard Memory Active Usage     0.003726
  Analytics Logs Data Ingestion    0.000000
  -----------------------------  ----------
  TOTAL                            0.169417

**There is no "Environment Management Hour" row.** The same query run against
the whole subscription rather than this resource group also returns no meter
whose name contains "Environment". So the expectation recorded under Reading 1
was correct: that meter is billed against Dedicated workload profiles, and this
environment is Consumption-only, so it is not charged. The uncertainty that
made this file necessary is resolved, and the answer is the cheaper one.

Cross-checked against a second, independent source. The budget object reports
its own spend figure:

  az consumption budget list
  insureassist-10usd  amount 10.0  timeGrain Monthly  currentSpend 0.169417 EUR

That is the same number to all printed digits, from a different API than the
Cost Management query above.

Daily split, same query at Daily granularity:

  2026-10-19   0.096115 EUR   (partial day, deployed ~12:21 UTC)
  2026-10-20   0.073302 EUR   (partial day, read at 18:57 UTC)

So the run rate is about **0.17 EUR/day**, and the ACR Basic registry unit is
89% of it. The compute is 0.0186 EUR over thirty hours, which is what
min-replicas 0 and no traffic should look like.

Health at the time of this reading:

Decision under the rule agreed with the owner: no charge appeared on the
Environment Management Hour meter, so rg-insureassist is **not** deleted
immediately. It stays up for seven days from deployment so the URL is usable in
applications, which puts teardown on **26 October 2026**. Seven days at the
measured rate is about 1.19 EUR against roughly 88 USD of remaining credit.
